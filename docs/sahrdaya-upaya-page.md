## Round 2, piece 4: the Reflections page (`/c/reflections`)
- **Drawn by** `public/circle/sahrdaya.js` (it now serves `/c/mentorship` and `/c/reflections`; `today.js` loads it for both), for mentees and Circle admins. Header, a four-step strip (Draft · Shared · Revised · Posted to SS), a list (this month's cohort · Mine · Posted to SS, a dot on ones you haven't read), and a reader/editor.
- **Flow:** **Write** → **Share with the cohort** (they read and comment) → **Revise** (a new version; earlier versions are kept and never edited; paragraphs changed since the version before are highlighted) → **Post to Sādhana School** (a confirmation shows how the post will look). Mentees may post whenever they are ready (no approval) and there is no anonymous option (Jacob did not ask for it). **Take it down** deletes the Circle post and the reflection goes back to "shared".
- **Feedback:** three kinds, each with a prompt (What landed · A question · A suggestion), replies one level deep, and while revising the author ticks the feedback they worked from: the commenter sees "Addressed in version n". Only mentees and Circle admins see any of it. No emails.
- **Data (Neon, made on first use):** `mentee_reflections` (author, month, topic, status draft|shared|posted, posted post id and url), `mentee_reflection_versions` (n, title, body, `shared_at`: a shared version is never edited; a revision is a new row), `mentee_reflection_comments`, `mentee_reflection_reads`. Code: `lib/mentee/reflections.js` (pure), `lib/mentee/reflectionstore.js`, API `/api/member/reflections`.

The post id is stored (`posted_post_id`), which is how the Sādhana School Reflections tab marks it. Pressing Post twice makes one post. Take-down tries the member API first, then the Admin API (`DELETE /posts/{id}`): neither is verified against real Circle, so the first real post and the first take-down after deploy are the tests (a failure leaves the reflection safe and says so).

## Practicum pods (mentees practise teaching each other)
Not the same as **articulation buddies** (the two people, or three when the numbers are uneven, the team pairs each rotation; set in the Mentee Partners tab). A **practicum pod** is a time a mentee organises to practise teaching with other mentees. **Anyone in the cohort can organise one; there is no approval.**
- **On the Sahṛdaya Upāya page**, the **Practicum pods** card: upcoming pods (what they will practise, when in the viewer's own time, organiser, places left), **Join** / **Leave**, **Organise a pod** (what to practise, day and time, 30–120 minutes, optional notes and live room link), the organiser can cancel. Members get **Join the live room** (and an optional pod chat link) and a shortcut to **Log practice-teaching hours**.
- **Live rooms:** the organiser makes a room in Circle's live rooms and pastes its link (steps are on the pod and in the form); only the pod's members see it.
- **Rules** (`lib/pods/practicum.js`): up to 6 people including the organiser; a time in the future and within 90 days; up to 3 upcoming pods per organiser; a pod disappears 3 hours after it ends; only mentees (and Circle admins) can see or use it. API: `/api/member/practicum`. Tables `practicum_pods`, `practicum_members` (made on first use).
- Test: `scripts/member-test/practicum.mjs` (PGlite).
- Wording: the page now says "articulation buddy" for the pair and keeps "pod" for study pods and practicum pods.
