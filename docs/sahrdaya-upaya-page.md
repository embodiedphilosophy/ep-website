# Sahṛdaya Upāya page (mentees only, `/c/mentorship`)

Built from the handoff of 21 Oct 2026. It holds only what is unique to mentees; practice, teaching and the Wednesday sessions stay on Today and the Sādhana School hub.

- **Drawn by** `public/circle/sahrdaya.js` (loaded by `today.js`, no frame). It sets `window.__epMentee` to `yes`/`no`; `season-loader.js` waits for that (up to 12 s) on `/c/mentorship` and shows the hub's mentor tab to non-mentees only.
- **Data:** the same `/api/member/this-week` call as "This week" (`lib/mentee/load.js`), now with a `home` block from `lib/mentee/home.js`: next immersion, Prepare opening (14 days before the Saturday), one-to-one window, peer partner, recent hours.
- **Config:** `data/mentee.json` (space ids, chat/workbook/booking links, `immersions`, `windows`, `pinned`). `message_url` is Jacob's Circle profile (`/u/151793d1`); `reflections_url` points at the Reflections space.
- **Peer partners:** sheet tab `Mentee Partners` (season | month | email_a | email_b | name_a | name_b | publish). Card hidden when no pairing. No Ops editor yet (the Settings editors live in ep-ops).
- **Log hours (P1):** mentees log observation, practice-teaching, peer articulation or retreat practicum. Entries are `pending` (`member_formation.status`) and only count toward the 100 hours once Jacob confirms. Existing staff rows stay `credited`.
- **Hand in (P1):** `Mentee Assignments` rows with `type = handin` get a Hand in form. Extra columns: `brief` (shown in the form), `hours_component` (observation | practice-teaching | peer | retreat) and `hours` (offers "Also log N hours"). Stored in `mentee_submissions` (draft, submitted, returned). Never touches the Travelogue.
- **Files:** go straight from the browser to a PRIVATE Vercel Blob store using `SUBMISSIONS_BLOB_TOKEN` (or `SUBMISSIONS_READ_WRITE_TOKEN`, which Vercel creates when the store is connected with the prefix `SUBMISSIONS`) (not the public ep-media store). Without that variable the file field is hidden and text hand-ins still work. The browser upload helper is `public/circle/blob-client.js` (rebuild: `scripts/circle-build/README.md`). Mentors open files through short-lived signed links (`/api/member/file`).
- **Jacob's side:** on `/c/today` the mentor view has a "Waiting for you" card: Confirm / Decline hours, Mark returned for hand-ins (`/api/member/submissions`, Circle admins only).
- **Reflections:** see "Round 2, piece 4" below. They no longer count from posts in the Mentorship Circle.
- **Cohort chat:** the room shows the latest messages, read-only, read as the signed-in member (`lib/school/circle.js` `chatMessages`, room id `chat_room_uuid` in `data/mentee.json`). Messages from Circle admins and moderators get a MENTOR tag. Sending is still the "Open the cohort chat" button: the send-message request has not been verified and a test would post to the real chat.
- **Sending to the cohort chat:** a message box under the chat sends as the signed-in member (`sendChatMessage`, `/api/member/this-week/chat`, rate-limited, 1,500 characters). The request format comes from Circle's own "missing parameter: rich_text_body" error and the shape messages are read back in; it has NOT been tried against the live chat (a test post to the mentees' room was not run). First real send after deploy is the test: if it fails the mentee sees "We couldn't send that just now" and the full-chat button still works.

Tests: `node --import ./scripts/ce-test/register.mjs scripts/member-test/mentee-home.mjs`
- **One-to-one times:** `lib/mentee/calendly.js` reads the open times in the current window and the mentee's own booking from Calendly (read-only; `CALENDLY_TOKEN` with users:read, event_types:read, availability:read, scheduled_events:read; event type id in `data/mentee.json` as `calendly_event_type`). Times show as chips that open Calendly at that slot; a booked mentee sees "Booked: …". Without the token the page shows the booking button as before. Calendly only shows slots once booking opens for the window.
- **Workbook progress:** `courseSections` (lib/school/circle.js) reads the Apprentice Workbook's sections with this member's lesson progress. Each immersion section ("1 · Beneath the Pose · …") has Prepare, Practicum and Integrate lessons: the Prepare button links to the lesson and shows "Done ✓" once completed, and after an immersion an Integrate card appears (for three weeks) until that lesson is completed. The "Start Here" lessons list with their status when no assignments are due. Lesson links use Circle's course address pattern `/c/apprentice-workbook/sections/{section}/lessons/{lesson}` (Circle's API does not return lesson addresses; click-test one).
- **Setting peer partners (Ops → Settings → Peer partners, `/ops/settings/partners`):** Jacob, Irene and Floss pick a month (it opens on next month after the 20th), press Suggest pairs (people from the Sahṛdaya Upāya Kit tag; avoids repeating earlier months' pairs; an odd number makes one group of three), adjust with the dropdowns, and Save. Mentees see their partner on their page straight away; nothing changes for them before Save. Saves go through `lib/ops/store.js` (`Mentee Partners` tab, created on the first save, change-logged, conflict-checked). Nothing is deleted: a pair taken out is hidden (`publish = FALSE`) and shows again if put back. A group of three is stored as its three pairs, so each person sees the other two. Logic in `lib/ops/partners.js`, API `app/api/ops/partners/route.js`, test `scripts/ops-test/partners.cjs` (against the mock) and `scripts/member-test/partners.mjs` (offline).
- **Surveys ("which time works?"), e.g. the mentorship orientation:** a card at the top of the mentee page lists the options (grouped by day, in the mentee's own time zone); they tick every time that works and Save (they can change it until a time is confirmed). Options live on the `Mentee Polls` tab, edited in Ops → Settings → Sahṛdaya Upāya → Polls (one row per time, like `2026-10-24 10:00 ET`; ET, UK or UTC). Answers are stored per mentee (`mentee_poll_votes`). Jacob sees who chose what, and who hasn't answered, at Ops → Settings → "see survey answers" (`/ops/settings/polls`). To confirm a time: set Final = Yes on that row (and add the meeting `link`); mentees then see the confirmed time instead of the survey, until two hours after it. `Closes` is optional. Logic in `lib/mentee/polls.js`, tests `scripts/member-test/polls.mjs` and the `polls db` section of `mentee-db.mjs`, `scripts/ops-test/su-settings.cjs`. The Settings group "Sahṛdaya Upāya" also edits the other Mentee tabs (Assignments, Weekly reading, Teaching feedback, Coming soon), so they no longer need editing in the sheet.
- **Reading list ("Book of the month"):** a card on the mentee page shows this month's required book (feeds the monthly written reflection) and suggested book (peer articulation, not assessed), each with a "Buy on Amazon.co.uk / Amazon.com" button (UK students by browser time zone or language get .co.uk, everyone else .com), a line about next month, and "See all the books", a popup with the whole list (this month highlighted). The list is the `Mentee Books` tab, edited in Ops → Settings → Sahṛdaya Upāya → Reading list: one row per book (`month | starts | theme | kind | title | author | audio | note | search | asin | publish`). The page moves to the next month by itself on each month's `starts` date. Links search Amazon for the title and author unless a book has an `asin` (the 10-character Amazon id) or a `search` override. Seeded 21 Oct 2026 with the 2026–27 list (Month 1 starts 21 Oct, then the 1st of each month from November: edit the dates if the months should run differently). Logic `lib/mentee/books.js`, test `scripts/member-test/books.mjs`.

## Round 2, piece 4: the Reflections page (`/c/reflections`)
- **Drawn by** `public/circle/sahrdaya.js` (it now serves `/c/mentorship` and `/c/reflections`; `today.js` loads it for both), for mentees and Circle admins. Header, a four-step strip (Draft · Shared · Revised · Posted to SS), a list (this month's cohort · Mine · Posted to SS, a dot on ones you haven't read), and a reader/editor.
- **Flow:** **Write** → **Share with the cohort** (they read and comment) → **Revise** (a new version; earlier versions are kept and never edited; paragraphs changed since the version before are highlighted) → **Post to Sādhana School** (a confirmation shows how the post will look). Mentees may post whenever they are ready (no approval) and there is no anonymous option (Jacob did not ask for it). **Take it down** deletes the Circle post and the reflection goes back to "shared".
- **Feedback:** three kinds, each with a prompt (What landed · A question · A suggestion), replies one level deep, and while revising the author ticks the feedback they worked from: the commenter sees "Addressed in version n". Only mentees and Circle admins see any of it. No emails.
- **Data (Neon, made on first use):** `mentee_reflections` (author, month, topic, status draft|shared|posted, posted post id and url), `mentee_reflection_versions` (n, title, body, `shared_at`: a shared version is never edited; a revision is a new row), `mentee_reflection_comments`, `mentee_reflection_reads`. Code: `lib/mentee/reflections.js` (pure), `lib/mentee/reflectionstore.js`, API `/api/member/reflections`.
- **Posting:** `createPost` as the mentee into the Reflections space of Sādhana School (Kula Commentary, 2896660: `reflections_space_id` in `data/school-hub.json` settings, else `data/mentee.json`), title = the reflection's title, body = the final shared version plus "From the Sahṛdaya Upāya cohort". The post id is stored (`posted_post_id`), which is how the Sādhana School Reflections tab marks it. Pressing Post twice makes one post. Take-down tries the member API first, then the Admin API (`DELETE /posts/{id}`): neither is verified against real Circle, so the first real post and the first take-down after deploy are the tests (a failure leaves the reflection safe and says so).
- **Counting:** **9 reflections count, each only once it is posted to Sādhana School** (Jacob, 1 Nov 2026). Each posted reflection is one automatic line of 6 ÷ 9 = 0.67 hours in "Monthly reflections", capped at 6; a reflection taken down stops counting. Nothing is stored as hours.
- **Evergreen card 3:** this month's title and "Version 2 · 3 comments from the cohort · ready when you are", "New in the cohort: n reflections you haven't read", **Open Reflections** (`reflections_url`) and **Post to SS** (only once shared; opens the confirmation at `/c/reflections?post=<id>`).
- Tests: `scripts/member-test/reflections.mjs` (PGlite), `reflections-route.mjs` (the real route, PGlite and the Circle mock: privacy, feedback, one post, take-down), `mentee-home.mjs`.
